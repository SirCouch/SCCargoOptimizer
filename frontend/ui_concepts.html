App UI concepts

Five directions for the whole application shell — not just the 3D boxes this time. The reference mockup shows today's layout (top row of Ship / Presets / Theme group boxes, manifest splitter, tabbed viewer, full-width optimize button, status bar). Each concept below rearranges the same real parts: ship + capacity, the manifest editor, presets, the Three.js viewport, metrics, the optimize action, and model status.

Every mockup is drawn with the actual palette values from desktop_app.py / viewer.html — use the palette switcher to see any concept in all eight manufacturer themes (including light Origin). Priority chips and the crates in the fake viewport use the app's default priority colors.

Concepts A–E — proposed shells

A

Command Rail

Sidebar-first. The top row of group boxes collapses into a slim icon rail plus one side panel that stacks ship, manifest, presets and the optimize action in a single vertical flow — set up the run top-to-bottom, then press the button at the bottom of the same column. The viewer takes everything else, with metrics and the legend floating over it, and the status bar only spans the work area. The rail's extra icons give settings/help a home without stealing space.

Qt mapping: straightforward — the rail is a fixed-width QToolBar, the side panel is the existing cargo pane plus the ship/preset widgets re-parented into it, and the splitter survives between panel and viewer. Lowest-risk of the five; no change to the viewer page itself.
B

Overlay HUD

Viewer-first: the 3D scene is the app, edge to edge, and every control floats over it as a translucent glass panel — the same language as the viewer's existing HUD and legend, applied to the whole shell. Ship card top-left, a pinnable manifest drawer on the right, live metrics in a top pill, and optimize as a floating action at the bottom center where it never leaves your line of sight. Panels collapse to edge tabs when you want a clean look at the hold.

Qt mapping: the boldest structural change — the natural build is to move the manifest editor into viewer.html itself and let the Qt window become a thin frame around one QWebEngineView (the title-channel bridge already carries theme and colors both ways). Alternatively Qt widgets can float over the web view, at the cost of fighting native-window compositing.
C

Dispatch Desk

The logistics-software take. One compact app bar replaces all three group boxes: ship and preset pickers inline, optimize as the primary accent action on the right. Under it, a KPI strip keeps capacity, manifest load, success rate and utilization permanently visible instead of buried in the Summary tab. The manifest becomes a proper sheet with a toolbar (add, bulk-priority, clear) and the viewer keeps its tabs, with the priority legend promoted into the tab strip.

Qt mapping: closest to the current code — the app bar is a QToolBar with embedded combos, KPI tiles are plain styled widgets fed by the numbers _on_pack_done already computes, and the manifest/viewer splitter is untouched. Best choice if the goal is a cleaner v0.2 without touching the web side.
D

MobiGlas

The in-universe option: chamfered holographic panels, thin accent-glow borders, uppercase condensed labels and a faint scanline pass — the app reads like a ship terminal rather than a desktop tool. The palette accent drives all the glow, so Drake runs hot orange while RSI glows blue. Metrics sit in the header as instrument readouts, the optimize action is a charged plate at the bottom of the manifest panel, and the viewport gets HUD corner brackets.

Qt mapping: the chamfers, glow and scanlines are beyond practical QSS — this concept only lands properly if the shell moves into the web layer (see Concept B's architecture). Worth it as the "8-Bit-style sibling" for immersion: it would ship as a third Style next to Modern and 8-Bit rather than replacing them.
E

8-Bit Console

The retro style, finished. Today "8-Bit" squares off corners and swaps the font; this concept commits the whole shell: a chunky double-border frame, DOS-style title bar, dithered capacity gauge, a scene rendered at low resolution and upscaled with hard pixels, and a beveled push-button OPTIMIZE that looks like it clunks. The status line becomes a terminal prompt with a blinking cursor. Same layout skeleton as today, so it stays familiar.

Qt mapping: almost entirely achievable in the existing build_qss() retro branch — thicker borders, the dithered progress chunk, beveled button shadows and the terminal status line are all QSS + a fixed-font label. The pixelated viewport is a small change in viewer.html (render at half resolution with image-rendering: pixelated when the retro style is active).
All mockups are static HTML/CSS drawn with the palette dictionaries from desktop_app.py (THEME_PALETTES) and the default priority colors, so switching the palette above previews each concept exactly as the app would tint it — including the light Origin theme. The crates in every viewport are painted by one shared isometric canvas routine; Concept E renders it at low resolution and upscales for the pixel look. Nothing here is wired into the app yet — pick a direction (or a combination: C's KPI strip works inside A's shell) and it can be implemented next.
